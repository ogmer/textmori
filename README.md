# textmori

Tauri + SvelteKit + CodeMirror 6 で作った軽量テキストエディタ。

## 機能

- タブによる複数ファイルの編集(新規 / 開く / 保存 / 名前を付けて保存)
- **セッション復元** — 未保存の内容も含めて全タブを自動的に保持し、次回起動時にそのまま復元する(終了時に確認ダイアログは出さない)
- ウィンドウの位置・サイズ・最大化状態を自動的に保存し、次回起動時に復元
- ライト / ダーク配色を「システムに従う / ライト / ダーク」から選択可能(既定はシステムに追従)
- 未保存変更の表示と、タブを閉じる時の確認
- 検索・置換、undo/redo、行番号、矩形選択
- 行の折り返し切り替え、文字サイズを%単位でズーム(ステータスバーのボタンで比率変更)
- ステータスバー(行:列、選択文字数、行数/文字数、改行コード、文字コード)
- ウィンドウへのドラッグ&ドロップでファイルを開く
- CRLF / LF、UTF-8 / Shift_JIS / EUC-JP / UTF-16 を自動判別して開き、同じ形式で保存(ステータスバーから手動変更も可能)
- 保存は一時ファイル経由のアトミック書き込み(クラッシュ時に元ファイルを壊さない)
- 分割ビュー(右 / 下)で同じファイルの別の場所を同時に編集

シンタックスハイライトの言語パックは持たず、プレーンテキスト編集に特化している。

## ショートカット

| キー | 動作 |
| --- | --- |
| `Ctrl+N` | 新規タブ |
| `Ctrl+O` | ファイルを開く |
| `Ctrl+S` | 保存 |
| `Ctrl+Shift+S` | 名前を付けて保存 |
| `Ctrl+W` | タブを閉じる |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 次 / 前のタブ |
| `Ctrl+Z` / `Ctrl+Y` | 元に戻す / やり直し |
| `Ctrl+X` / `Ctrl+C` / `Ctrl+V` | 切り取り / コピー / 貼り付け |
| `Ctrl+A` | すべて選択 |
| `Ctrl+F` / `Ctrl+H` | 検索 / 置換 |
| `Alt+Z` | 行の折り返しを切り替え |
| `Ctrl+=` / `Ctrl+-` / `Ctrl+0` | ズーム 拡大(+10%) / 縮小(-10%) / 100%に戻す |

macOS では `Ctrl` の代わりに `Cmd`(`Alt+Z` は `Option+Z`)を使う。

## 開発

```sh
npm install
npm run tauri dev     # 開発用に起動
npm run tauri build   # 配布用にビルド
npm run check         # 型チェック
npm run test          # フロントエンドのユニットテスト(Vitest)
cd src-tauri && cargo test  # Rust 側のユニットテスト(文字コード判定・設定ファイルのパース等)
```

## 設計方針・非機能要件

- **状態の所在**: 開いているファイル一覧・dirty フラグ・カーソル位置などは
  すべて `Workspace`(Svelte 側、`src/lib/workspace.svelte.ts`)が唯一の正とする。
  Rust 側はアプリの状態を一切保持せず、ファイル I/O(`encoding.rs`)と設定ファイル
  I/O(`config.rs`)だけを担う純粋なコマンドの集合として実装している。
- **文字コード判定のフォールバック**: BOM → UTF-8 → Shift_JIS → EUC-JP の順に
  「完全に矛盾なく解釈できるか」を試し、どれにも合わなければ UTF-8 として
  置換文字付きで開く(`encoding.rs` の `detect_and_decode`)。この場合はダイアログで
  ユーザーに警告する。
- **保存の安全性**: 保存は同じディレクトリに一時ファイルを書き出してから
  `rename` するアトミック方式。書き込み中にクラッシュしても元のファイルは
  壊れない。
- **巨大ファイル**: CodeMirror 6 は仮想描画のため、サイズによる制限は設けず
  常に編集可能な状態で開く。非常に大きなファイルではファイル読み込み・保存
  そのものに時間がかかる場合があるが、編集自体をブロックすることはしない。
- **fs のスコープ**: ファイルの読み書きは常にユーザーがネイティブダイアログ
  (開く/名前を付けて保存)で明示的に選んだパス、またはセッション復元で
  それ以前に同様の経路で開いたパスに対してのみ行われる。任意の URL や
  リモートコンテンツは一切読み込まないため、Web 由来の XSS 経由でファイル
  システムへ到達する経路は存在しない。
- **IPC**: 現状は `invoke` 経由でファイル内容を文字列としてやり取りしている。
  数十 MB 級のファイルを頻繁に往復させる用途が増えた場合は、`tauri::ipc::Response`
  や `Channel` によるバイナリ転送への切り替えを検討する余地を残している
  (現時点では 10MB 程度のテキストファイル 1 回の読み書きが体感できるボトルネック
  にはなっていないため未対応)。
- **起動速度**: `onMount` では CodeMirror のマウントのみを同期的に行い、設定
  ファイルの読み込み・監視は非同期で後回しにしている。ネットワーク通信は
  行わない(自動更新機能は削除済み)。
- **対応 OS**: 開発のメインターゲットは Windows。macOS はネイティブメニュー・
  ウィンドウ装飾を使う分岐を用意しているが、実機での動作確認は主に Windows
  で行っている。
